oh-my-db

API & MCP reference

HTTP API

Base path /api. Mutating routes (marked 🔒) require Authorization: Bearer <token> when OHMYDB_AUTH_TOKEN is configured; unset by default.

GET /api/clustersConfigured cluster names.
GET /api/graph/{cluster}?q=Catalog nodes for one cluster (tables, views, materialized views, dictionaries, with labels). No edges. Optional q: substring match against name/database/labels, or key:value for an exact label lookup.
GET /api/entities/{cluster}/{database}/{name}Full entity detail: columns with types/comments, raw DDL, engine, attrs, labels.
GET /api/entities/{cluster}/{database}/{name}/relations?direct=Transitive upstream (data sources) and downstream (consumers). direct=true limits to immediate 1-hop neighbors.
PUT /api/labels/{cluster}/{database}/{table} 🔒Set a label. Body {"key": ..., "value": ...}.
DELETE /api/labels/{cluster}/{database}/{table}/{key} 🔒Remove a label.
POST /api/sync?cluster= 🔒Re-introspect and re-sync the catalog — all clusters, or one if cluster is given.

MCP tools

Mounted at /mcp over HTTP, or over stdio via ohmydb mcp. Same reads as the HTTP API.

list_clusters()Configured cluster names. Call this first — get_schema_graph requires one of these.
get_schema_graph(cluster)Catalog nodes for one cluster, with labels. No dependency edges — call get_table_relations for one entity's upstream/downstream.
get_table(cluster, database, name)Full detail for one entity: columns with types/comments, raw DDL, engine, attrs, labels.
get_table_relations(cluster, database, name, direct=False)Transitive upstream/downstream entities. direct=True for only immediate 1-hop neighbors.
find_tables(query)Search entities across all clusters. key:value does an exact label lookup; otherwise substring match against name, database, or any label key/value.
